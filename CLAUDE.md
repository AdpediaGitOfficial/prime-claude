# Prime Promenade — Architecture & Working Notes

A three-tier system for **Prime Promenade** (a multi-floor lifestyle destination in
Thrissur, Kerala: gym, spa, pool, conference hall, gaming arena, café, pharmacy,
study centre, vendor counters). This file is the durable memory of the codebase —
read it first, keep it updated when architecture changes.

## Backend (`backend/`)

Express app, Prisma/Postgres. Entry `src/server.ts`. Routes split into **public**
(`src/routes/public.routes.ts`) and **admin** (`src/routes/admin.routes.ts`, JWT-guarded).

### Response shapes (important convention)
- **Public endpoints** return the **raw** JSON shape the website expects (no envelope) —
  paths match the original static-site contract exactly so no frontend rewrite was needed.
- **Admin endpoints** return an envelope: `{ success, message, data, meta? }`. The admin
  `api()` client unwraps `.data`/`.meta`.

### Module pattern (`src/modules/<name>/`)
Each domain (pool-bookings, hall-bookings, spa, gym, vendor-invites, course-registrations,
contact-enquiries, listings, content, otp, uploads, dashboard, admin-auth, admin-users).

Shared factories in `src/modules/_shared/`:
- `resourceController.ts` → `createResourceController(config)` — generic list/get/create/update/status/delete.
- `resourceRouter.ts` → `buildResourceRouter(config)` — wires those to an Express router.
- `resources.ts` → **`RESOURCES`** registry: one config per admin resource (path, model,
  searchFields, sortFields, create/update Zod schemas). Admin routes are generated by
  looping `RESOURCES` and mounting `buildResourceRouter`. Add a new admin CRUD resource by
  adding an entry here.
- `commonSchemas.ts` (idParam, listQuery), `publicCreate.ts` (public form create helper).
- `content.crud.ts` → `createCrudController` for CMS collections (pages/banners/gallery).

Admin route mounts (`admin.routes.ts`): `/auth` (unguarded) → `authGuard` → `/dashboard`,
`/pool-bookings` (custom calendar routes, mounted **before** the generic router),
`RESOURCES` loop, `/` content, `/listings`, `/uploads`, `/admins`.

### Auth & security
JWT access + refresh (`RefreshToken` table). `authGuard` middleware. helmet, cors
(`CORS_ORIGINS` env), hpp, compression, rate-limit, morgan. Uploads via multer to
`/uploads` (served statically); `assetUrl()` builds absolute URLs on both frontends.

### Prisma / DB (`backend/prisma/schema.prisma`)
Models: `AdminUser`, `RefreshToken`, `OtpVerification`, `AuditLog`, `PoolBooking`,
`HallBooking`, `SpaBooking`, `GymMembership`, `VendorInvite`, `CourseRegistration`,
`ContactEnquiry`, `Page`, `Banner`, `GalleryImage`, `SiteSetting`, `Listing`.
Enums: `AdminRole`, `BookingStatus` (PENDING/CONFIRMED/CANCELLED/COMPLETED),
`LeadStatus` (NEW/IN_PROGRESS/RESOLVED/ARCHIVED), `ListingType`.

**Human-readable reference IDs** are DB-generated via Postgres sequences +
`@default(dbgenerated("('POOL-' || lpad(nextval(...)::text, 5, '0'))"))`:
- `PoolBooking.reference` → `POOL-00001`
- `HallBooking.reference` → `HALL-00001`
- `SpaBooking.reference` → `SPA-00001`
- `CourseRegistration.reference` → `ENR-00001`
Migrations are **hand-written** (in `prisma/migrations/`) with plpgsql `DO`-block backfills
for existing rows, and are **additive/idempotent** — deploy uses `prisma migrate deploy`.
When adding a reference/sequence, mirror the existing migration pattern.

### Pool booking domain (authoritative logic — the UI only mirrors it)
`src/modules/pool-bookings/poolAvailability.ts`:
- Hours: `OPEN_MIN = 600` (10:00 AM) … `CLOSE_MIN = 1320` (10:00 PM).
- **Two physical pools.** `POOL_SMALL = 1` (capacity ≤ 8), `POOL_GROUP = 2` (≤ 12).
- **Roles / eligibility** (`eligiblePools`): a **group** plan (`isGroupPlan` = `/group/i`
  on poolType) → **Pool 2 only**; a **small** plan → **Pool 1 first, overflow to Pool 2**
  (`[POOL_SMALL, POOL_GROUP]`). Business intent: the group pool is reserved for groups /
  used only when the small pool is occupied.
- **Flexible 30-minute start grid** (no fixed slots) to maximise utilisation; plan
  durations e.g. Solo/Duo 60m, Session 90m, Group longer.
- `assignPool(date, timeSlot, poolType, requestedPool?)` validates hours (400), eligibility
  (400), interval overlap per pool (`s1<e2 && e1>s2`), and full/conflict (409); returns the
  assigned pool id. Pool id is **admin-only** — stripped from customer responses.
- **Pricing:** GST **18%** (`Math.round(subtotal * 0.18)`), add-ons (Jacuzzi, Sauna Bath)
  **₹500 each**. Website shows price with a `*` and "*GST extra as applicable"; the sent
  `totalAmount` is GST-inclusive. Admin shows the full GST breakdown.

Pool booking is a **normal booking (no OTP)**. Email is **optional** on all booking forms.

Calendar endpoints (admin): `GET /pool-bookings/calendar?date=`, `GET /pool-bookings/month?month=`,
`POST /pool-bookings` (offline block). Public: `POST /pool-bookings` (direct create),
`GET /pool-bookings?date=` (per-pool occupied intervals for the picker).

## Public website (`prime-source-code/`)

Next.js **static export** → `out/` (rsynced to nginx web root). `next.config.ts`:
`output: "export"`, `images: { unoptimized: true }`. Because images are unoptimized and
export is static, **masonry / natural-height images use a plain `<img>`** (with the
`// eslint-disable-next-line @next/next/no-img-element` comment), not `next/image` with `fill`.

Brand look: black `#111`, lime accent **`#e1ff83`**, generous rounded corners.

**Vertical section rhythm:** use the reusable **`.section-y`** utility (in `globals.css`) for a
section's top/bottom padding — **64px / 96px (md) / 120px (lg)**, the same scale the service
pages express inline as `!py-16 md:!py-24 lg:!py-[120px]`. Pair with `site-container` for the
horizontal padding. Prefer `.section-y` over ad-hoc `py-*` so sections don't drift apart;
keep deliberate exceptions explicit (e.g. a banner tucked flush under the section above uses
`pb-0`/no top padding on purpose).

Key files:
- `src/utils/api.ts` — `apiCall()`, `assetUrl()`, and `ENDPOINTS` (POOL_BOOKINGS, HALL_BOOKINGS,
  SPA_BOOKINGS, GYM_MEMBERSHIPS, VENDOR_INVITES, COURSE_REGISTRATIONS, CONTACT_ENQUIRIES,
  LISTINGS, SITE_SETTINGS, BANNERS, GALLERY). API base resolves from
  `NEXT_PUBLIC_API_BASE_URL`, else same-origin `/backend` on a real domain, else localhost:5000.
- `src/utils/validation.ts` — **shared form validation** (see Validation below).
- `src/utils/useFormSubmit.ts` — submit-state hook: `{ isSubmitting, submitMessage,
  submitError, setSubmitError, runSubmit }`. Most forms use `formData` + `handleInputChange` +
  `handleSubmit` and surface errors via `submitError`.
- `src/components/Popup.tsx` — the announcement pop-up (see Pop-up below), mounted in `layout.tsx`.
- `src/app/gallery/page.tsx` — **masonry** gallery (CSS `columns-2 lg:columns-3`, plain `<img>`,
  `break-inside-avoid`), with a framer-motion lightbox.
- Routes: `/` (home), `/pool-booking`, `/spa`, `/conference` (hall), `/study-centre` (courses),
  `/gym`, `/contact`, `/vendor` + `/vendor-invite`, `/prime-x-arena`, `/cafe`, `/pharmacy`,
  `/about`, `/gallery`, `/terms`, plus confirmation pages.

## Admin dashboard (`admin/`)

Next.js 15, `basePath` `/admin` (`NEXT_PUBLIC_BASE_PATH`). Tokens in `localStorage`
(`pp_admin_access`/`pp_admin_refresh`); `src/lib/api.ts` `api()` adds the bearer, transparently
refreshes on 401, unwraps the envelope; `uploadFile()` for multipart.

- `src/components/Shell.tsx` — sidebar nav (groups: Overview, Manage, Catalog, Website) +
  `TITLES` map + theme toggle. Nav includes **Pool Calendar**, and top-level **Gallery** and
  **Pop-up** under Website (each managed separately).
- `src/components/ResourceTable.tsx` + `src/components/RecordPanel.tsx` — **generic** admin CRUD.
  A resource is a `ResourceConfig` (columns + `FieldDef[]`). `FieldDef.type` ∈
  text/email/tel/number/date/textarea/select. `RecordPanel` renders the create/edit form and is
  the **single place** name/phone validation is enforced for bookings/hall/enquiries/enrollments/gym
  (via `fieldKind()`/`validateForm()`). Add a resource by giving `ResourceTable` a new config.
- `src/components/BannersManager.tsx`, `GalleryManager.tsx`, `PopupManager.tsx`,
  `ImageUpload.tsx`, `Toast.tsx`.
- `src/lib/validation.ts` — admin copy of the shared validators.
- `src/app/(dashboard)/pool-calendar/page.tsx` — bespoke two-pool scheduler: month load bars
  (`/month`), day timeline **10 AM–10 PM axis**, `packLanes()` column-packs overlapping bookings
  side-by-side, past dates disabled, `ManageDrawer` (status/cancel/delete + GST breakdown),
  `BlockDrawer` (offline block: only-bookable start times, eligible+free pool restriction,

- Routes: `/` dashboard, `/bookings`, `/pool-calendar`, `/hall`, `/enquiries`, `/enrollments`,
  `/counters`, `/pool`, `/spa`, `/courses`, `/gym`, `/content`, `/gallery`, `/popup`.

**Admin CSS design tokens** (must exist in `admin` globals — do NOT invent new ones):

`--info`, `--bad`, `--brand`. (A past dark-mode bug came from using non-existent tokens like

## Cross-cutting features

### Form validation (name + phone, both apps)
Shared helpers: `prime-source-code/src/utils/validation.ts` and `admin/src/lib/validation.ts`
(kept in sync). Exports: `sanitizeName`, `sanitizePhone`, `isValidName`, `isValidPhone`,
`NAME_ERROR`, `PHONE_ERROR`.
- **Name** — letters (any language) + spaces + `. ' -` only; ≥ 2 letters; digits/specials
  blocked live and rejected on submit. Regex `^\p{L}[\p{L}\s.'-]*$/u`.
- **Phone** — exactly **10 digits, starting 6–9** (Indian mobile): `^[6-9]\d{9}$`. Inputs get
  `inputMode="numeric"` + `maxLength={10}` and strip non-digits live.
Applied to every public form (pool, spa, hall, courses, gym, contact, vendor invite/register/
counters; the static prime-x-arena form uses native `pattern`/`maxLength`) and all admin entry
forms. Backend still validates independently (defense-in-depth). Admin offline block allows a
**blank** guest name; if entered it must be valid.

### Announcement pop-up (no DB migration — reuses existing tables)
- **Slides** = `Banner` rows with `location = "popup"` (image + optional per-slide `ctaHref` +
  `order` + `isActive`). Public read: `GET /banners?location=popup`.
- **Config** = one `SiteSetting` key **`popup`**: `{ enabled, autoplay (seconds, 0=manual),
  frequency: "session"|"daily"|"always", scope: "home"|"all" }`. Public read via `GET /site-settings`.
- `Popup.tsx` (site): image-only carousel (arrows, dots, autoplay, Esc/←/→), frequency gating
  via session/localStorage, scope gating via `usePathname`. Ships **OFF** by default.
- `PopupManager.tsx` (admin, `/popup`): master switch, upload/reorder/hide/delete slides, per-slide
  link, behaviour settings.

### Gallery
Managed at admin `/gallery` (`GalleryManager`), public `/gallery` shows a masonry grid. Gallery
image form fields: image, title (optional), order, active (Category was removed).

## Build, test, deploy

### Local dev
- Backend: `npm run dev` (ts-node-dev). Typecheck `npm run typecheck`. Prisma: `prisma:migrate`,
  `prisma:deploy`, `prisma:generate`, `seed`.
- Frontends: `npm run dev`. Verify with `npx tsc --noEmit` then `npm run build`.
- Test DB pattern used in this project: local Postgres cluster on **port 5433**
  (`DATABASE_URL="postgresql://postgres@localhost:5433/prime_promenade?host=/tmp"`), detached
  servers via `setsid`, browser tests with playwright-core + `/opt/pw-browsers/chromium`,
  static site served via `serve out -l 8080`.

### Deploy (single VPS, nginx + pm2)
`./deploy/deploy.sh` (run from repo root, from `/opt/prime` on the server):
1. `git fetch` + `pull --ff-only` the current branch (refuses a diverged history).
2. Backend: `npm ci`, wipe `dist`, `npm run build`, `prisma generate`, **`prisma migrate deploy`**
   (idempotent), optional `--seed` (first deploy only).
3. Admin: `npm ci`, wipe `.next`, build with `NEXT_PUBLIC_API_BASE_URL` + `NEXT_PUBLIC_BASE_PATH`.
4. Site: `npm ci`, wipe `.next out`, build, `rsync -a --delete out/ → web root`.
5. `pm2 restart pp-api pp-admin`.
Flags: `--no-pull`, `--seed`. Env overrides: `API_BASE_URL`, `ADMIN_BASE_PATH`, `SITE_WEB_ROOT`,
`SUDO`. pm2 apps: **`pp-api`**, **`pp-admin`**. Full runbook: `deploy/DEPLOYMENT.md`.

**Conflict-free update** = the deploy is hardened against the three conflict sources: git
(ff-only), DB (idempotent additive migrations), stale build chunks (wipes `dist`/`.next`/`out`).
Content-only pop-up/gallery changes need no migration.

## Conventions & gotchas (read before editing)
- Match surrounding code style; keep public API paths/shapes unchanged (frontend contract).
- Public = raw shape; admin = `{success,message,data,meta}` envelope.
- The **backend is authoritative** for pool hours/overlap/roles/pricing; UI mirrors, never trusts.
- Static site: use plain `<img>` for natural-height images; `next/image` needs width/height or `fill`.
- Admin dark mode: only use the real CSS tokens listed above.
- After changing a Prisma `select`, **rebuild the backend** (`npm run build`) before testing dist.
- Prisma migrations must stay additive/idempotent; hand-write backfills in plpgsql `DO` blocks.
- Rebuild the relevant Next app after component/schema changes; both apps must `tsc --noEmit`
  clean and `next build` clean before commit.
- Model identity (`claude-opus-4-8`) must never appear in commits/PRs/code — chat only.
